# 项目保护机制与任务执行规范

## 一、核心保护原则

### 1. Git保护策略
- **所有任务前必须创建快照**：每个任务开始前自动创建Git快照分支
- **分支命名规范**：
  - `backup/snapshot-{任务ID}-{时间戳}` - 任务快照
  - `backup/stable-{日期}` - 稳定版本标记
  - `backup-before-work` - 永久保留的安全备份点
- **Commit规范**：所有commit必须包含清晰的任务描述

### 2. 兜底恢复机制
- **自动备份**：每次危险操作前自动备份当前状态
- **快速回滚**：可在3秒内恢复到任意历史版本
- **多重保护**：本地Git + 备份分支 + 快照点

### 3. 风险评估机制
所有命令执行前必须进行风险评估，分类如下：

#### 🔴 高风险命令（需二次确认）
- `git reset --hard`
- `git clean -f`
- `rm -rf` 或 `Remove-Item -Recurse -Force`
- `git push --force`
- 删除文件操作
- 修改多个文件的批量操作

#### 🟡 中风险命令（需明确目的）
- `git checkout`
- `npm install` / `pip install`
- 任何修改配置的命令
- 网络请求命令

#### 🟢 低风险命令（可自动执行）
- `git status`
- `git diff`
- `git log`
- 只读操作

## 二、自动保护流程

### 任务开始前
1. 检查工作目录状态
2. 如有未提交更改，先暂存或提交
3. 创建任务快照分支
4. 记录当前版本SHA
5. 评估任务风险等级

### 任务执行中
1. 危险操作前自动创建备份
2. 分步执行关键操作
3. 定期自动commit进度
4. 实时监控异常

### 任务完成后
1. 验证功能正常
2. 创建稳定版本标记
3. 清理临时分支
4. 记录完成状态

## 三、命令执行安全检查

### 强制检查清单
- [ ] 命令是否在风险白名单中
- [ ] 是否有对应的备份快照
- [ ] 操作范围是否明确
- [ ] 是否影响多个文件
- [ ] 是否有回滚方案

### 危险命令黑名单
```
# 禁止直接执行的命令
git reset --hard HEAD
git clean -fd
rm -rf ./*
Remove-Item -Path ./* -Recurse -Force
git push --force-with-lease
```

## 四、恢复机制

### 快速恢复命令
```powershell
# 恢复到上一个稳定版本
git reset --hard backup/stable-latest

# 恢复到特定快照
git reset --hard backup/snapshot-{id}

# 查看所有备份
git branch -a | Select-String backup
```

### 紧急恢复流程
1. 立即停止当前操作
2. 使用 `git status` 确认当前状态
3. 执行 `git reflog` 查看历史
4. 恢复到安全的commit
5. 验证文件完整性

## 五、任务执行模板

### 每个任务的标准化流程

#### 阶段1：准备（5秒）
```
[ ] 评估任务风险等级
[ ] 检查Git状态
[ ] 创建任务快照（自动）
[ ] 记录当前版本SHA
```

#### 阶段2：执行
```
[ ] 按照风险等级执行
[ ] 危险操作前确认
[ ] 分步执行关键步骤
[ ] 实时监控错误
```

#### 阶段3：验证
```
[ ] 测试修改是否生效
[ ] 检查文件完整性
[ ] 确认无语法错误
[ ] 创建稳定版本标记
```

## 六、责任与权限

### AI助手职责
- 每次操作前检查保护机制是否就绪
- 自动创建备份快照
- 评估并告知风险等级
- 执行前获得明确授权
- 记录所有重要操作

### 用户职责
- 提供任务明确目标
- 对高风险操作进行二次确认
- 定期检查备份完整性
- 提供反馈和改进建议

## 七、配置管理

### 保护级别设置
- **严格模式（默认）**：所有操作前检查
- **标准模式**：危险操作前检查
- **宽松模式**：仅自动备份

### 白名单管理
在 `.trae/protection_config.json` 中配置信任的命令列表。

## 八、监控与日志

### 操作日志
所有重要操作记录到 `.trae/operation_log.md`

### 定期检查
- 每日：检查备份分支数量
- 每周：清理过期快照
- 每月：验证备份完整性

## 九、例外情况

### 紧急修复
如遇紧急情况，可跳过部分检查，但必须：
1. 口头说明风险
2. 立即创建备份
3. 事后补充文档

### 用户明确指示
如用户明确要求执行危险操作，AI必须：
1. 再次确认意图
2. 创建额外备份
3. 记录在操作日志
4. 执行后立即验证
